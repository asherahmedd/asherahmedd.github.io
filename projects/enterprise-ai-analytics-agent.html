01 / Project overview

Making enterprise analytics conversational.

AI-Powered Analytics Agent for SAP is an enterprise conversational analytics initiative that helps users ask business questions in natural language and receive insights grounded in enterprise data. The solution separates natural-language reasoning from data retrieval: MCP exposes approved analytical tools, OData serves modeled business measures from SAP Datasphere, and the assistant formats the results as understandable KPI answers. The LLM does not need unrestricted SQL access.

My work has focused on the SAP data and integration side: preparing analytics-ready views in SAP Datasphere, exposing governed data through service interfaces, and supporting tool-driven consumption by AI applications.

04 / Example workflow

An illustrative KPI request.

Consider a question such as: “What are our total sales?” The conversation layer interprets the intent, chooses an available analytical tool, calls a governed data service and returns a value with business context.

REQUEST → TOOL → DATA → RESPONSE
  1. Interpret the user's business question and identify the relevant metric.
  2. Invoke an approved tool with structured input rather than giving the model unrestricted database access.
  3. Read the metric from SAP Datasphere through an exposed service.
  4. Return the KPI with clear labels and business context.

This walkthrough is illustrative, uses no live customer values, and does not imply autonomous execution of business transactions.

06 / Engineering takeaways

What matters for enterprise AI.

  • Semantics come first. An AI experience is only as reliable as the definitions and data behind its tools.
  • Tools need boundaries. Service permissions and identity-aware authorization belong in the integration design, not in prompts alone.
  • Concurrency deserves testing. Request and user context must remain isolated when several conversations happen in parallel.
  • Explainability builds trust. KPI names, filtering context and transparent tool outputs make analytical answers easier to validate.
Engineering challenges & safeguards

Making AI Answers Reliable.

Getting an AI agent to respond is only part of the problem. The harder task is grounding each answer in the right business definition, source data and authorized scope. These safeguards reduce hallucination risk; they cannot guarantee that every response will be error-free.

01Hallucinated KPIs

Challenge: An LLM can produce a convincing number even when no trusted data was retrieved.

Control: Define KPIs in governed SAP Datasphere assets and retrieve their values through approved analytical tools. The model explains tool results; it is not the source of business figures.

02Incorrect Business Context

Challenge: The same KPI can produce conflicting answers when currency, date range, filters or aggregation rules are misunderstood.

Control: Use semantic contracts that declare the metric definition, grain, allowed dimensions, reporting period and currency. Validate tool inputs before making a request.

03Ambiguous or Unsupported Questions

Challenge: Natural-language requests may omit essential details or ask for measures the data platform cannot supply.

Control: Resolve missing context through a clarification question, and explicitly decline unsupported queries rather than silently substituting a similar metric.

04Data Security & Access

Challenge: A conversational interface must not become a way to retrieve sensitive information outside a user's permissions.

Control: Authenticate users, enforce authorization at the tool boundary, and respect SAP Datasphere access controls and data access restrictions.

05Trust, Testing & Validation

Challenge: A numerically correct answer can still be misleading when it references the wrong period, organizational scope or data freshness.

Control: Compare outputs with approved reference reports; test known questions, negative cases and access boundaries. Present the reporting context and handle retrieval failures clearly.
